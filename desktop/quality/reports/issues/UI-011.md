# UI-011 — Create-collection name input has no accessible name

- Classification: confirmed defect
- Severity: P2 Medium (screen-reader users cannot identify the field)
- Confidence: confirmed
- Area: `src/screens/CollectionsScreen`
- Affected format/platform: all platforms
- First observed: 2026-11-28 baseline audit
- Commit/build: `ed7a3a1`

## User impact
The "New collection" textbox is announced as an unlabeled edit field. A screen
reader user cannot tell what to type without relying on surrounding context.

## Reproduction steps
1. Open Collections and start creating a new collection.
2. Inspect the focused textbox's accessible name with a screen reader or axe.

## Expected
Textbox has an accessible name, e.g. "Collection name", as the rename dialog
already does.

## Actual
Only a `placeholder` is present; no `<label>` or `aria-label`.

## Evidence
- `src/screens/CollectionsScreen.tsx:304-318` — input has `placeholder`,
  `aria-invalid`, `aria-describedby`, `autoFocus`, no accessible name.
- Rename counterpart at `:479-493` includes `aria-label="Collection name"`.
- `tests/a11y.test.tsx` covers other primitives but not this dialog.

## Root cause
The newer create dialog omitted the labeling used by the rename dialog.

## Proposed minimal fix
Add `aria-label="Collection name"` to the input (or a real `<label>`), keeping
the existing error description linkage.

## Regression test
Render/create the dialog and assert
`getByRole("textbox", { name: /collection name/i })`; add an axe assertion for
the open dialog.
