# UI-014 — Combobox options were extra tab stops

- Classification: confirmed defect
- Severity: P2 Medium
- Confidence: confirmed (RED test → GREEN)
- Area: `src/components/CommandPalette`, `src/screens/LibraryScreen`
- Commit/build: `ed7a3a1`

## User impact
Both the command palette and library search use `role="combobox"` with `aria-activedescendant`, but their `role="option"` buttons remained normal tab stops. Tab could move focus into the list while `aria-activedescendant` still pointed elsewhere, producing a mixed focus model.

## Evidence
- New assertion in `tests/commandPalette.test.tsx` failed RED: options had `tabIndex === 0`.

## Applied minimal fix
Added `tabIndex={-1}` to the `role="option"` buttons in `CommandPalette` and the Library search results list. Clicking still works; Arrow/Enter/Escape handling on the combobox input is unchanged.

## Regression test
`tests/commandPalette.test.tsx` now asserts every option has `tabIndex === -1` and the combobox has a non-empty `aria-activedescendant`.
