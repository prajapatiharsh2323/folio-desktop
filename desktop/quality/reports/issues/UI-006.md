# UI-006 — Keep-awake confirmation messages are inverted

- Classification: confirmed defect
- Severity: P2 Medium (misleading status feedback)
- Confidence: confirmed
- Area: `src/screens/SettingsScreen`
- Affected format/platform: all platforms
- First observed: 2026-11-28 baseline audit
- Commit/build: `ed7a3a1`

## User impact
Turning **Keep screen awake** On tells the user display sleep is allowed again;
turning it Off says the display will stay awake. The stored setting and the
chip state are correct, so users can be actively misled about the outcome.

## Reproduction steps
1. Open Settings → Reading → Keep screen awake.
2. Click **On**. Read the status message.
3. Click **Off**. Read the status message.

## Expected
On → "The display will stay awake while reading."; Off → "Display sleep is
allowed again."

## Actual
The two strings are swapped.

## Evidence
- `src/screens/SettingsScreen.tsx:216-232`: `:223` writes
  `preventSleepWhileReading: enable`; `:224-226` says "Display sleep is allowed
  again." when `enable === true` and the opposite when false.
- Chip label at `:684` matches the stored meaning (`On` keeps awake),
  confirming the message is the wrong part.
- No existing test asserts these status strings (`tests/settings.test.tsx`).

## Root cause
Copy strings were assigned to the wrong branches of the ternary.

## Proposed minimal fix
Swap the two message strings in the ternary. Optionally assert via a small
settings test that toggling On/Off produces the matching status text.

## Regression test
`tests/settings.test.tsx`: click On → expect status "The display will stay
awake while reading."; click Off → expect "Display sleep is allowed again."
