# UI-007 — Destructive “Delete everything” used primary styling

- Classification: confirmed defect
- Severity: P3 Low
- Confidence: confirmed (RED assertion → GREEN)
- Area: `src/screens/SettingsScreen`, `src/components/FolioButton`
- Commit/build: `ed7a3a1`

## User impact
The irreversible full-data-deletion button was visually promoted as the primary action instead of using the established danger style, weakening the warning and increasing mis-click risk.

## Reproduction / evidence
- Open Settings → Reset app data; inspect the “Delete everything” button classes.
- Before fix: `folio-btn--primary`; after fix: `folio-btn--danger`.

## Root cause
The reset dialog was authored before the danger variant was used consistently elsewhere.

## Applied minimal fix
Changed `variant="primary"` to `variant="danger"` on the confirm button; existing confirmation checkbox, dialog copy and disabled-until-confirmed behavior unchanged.

## Regression test
`tests/settings.test.tsx` reset-flow test now asserts the confirm button has `folio-btn--danger` and not `folio-btn--primary`.
