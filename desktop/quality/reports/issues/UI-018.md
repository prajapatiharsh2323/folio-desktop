# UI-018 — Undefined CSS custom properties break palette, skeleton and focus visuals

- Classification: confirmed defect
- Severity: P2 Medium (visible rendering defects; focus indicator affected)
- Confidence: confirmed (CSS inspection)
- Area: `src/styles/tokens.css`, `src/styles/components.css`
- Affected format/platform: all screens/themes; all platforms
- First observed: 2026-11-28 baseline audit
- Commit/build: `ed7a3a1`

## User impact
Several shared styles reference custom properties that are never defined and
have no fallback. CSS drops those declarations, so: palette/appearance rows
have square corners and no elevated surface, the active command-palette row is
not highlighted, skeleton shimmer gradients are missing, and the normal-theme
focus outline color is invalid.

## Reproduction steps
1. Open the Command palette (Ctrl+K) and arrow down: the active option has no
   visible highlight.
2. Observe palette/menu corners and skeleton loading placeholders: flat,
   unsurfaced, square.
3. Inspect computed styles: declarations with `var(--folio-radius)`,
   `var(--folio-bg-elevated)`, `var(--folio-bg-active)`, `var(--folio-focus)`
   are invalid at computed-value time.

## Expected
Every `var(--folio-*)` reference resolves to a defined token or supplies a
fallback.

## Actual
Nine tokens are referenced but never defined (outside a forced-colors block
for `--folio-focus`).

## Evidence
Referenced without definition/fallback (grep comparison of all
`var(--folio-*)` references against definitions in `src/styles/*.css`):
`--folio-radius`, `--folio-bg-elevated`, `--folio-bg-active`, `--folio-focus`,
plus reader-only ones that DO supply inline fallbacks
(`--folio-radius-md`, `--folio-text-strong`, `--folio-type-note-size`,
`--folio-type-small-size`, `--folio-progress`, `--folio-linefocus-dim`).
Affected component locations: `components.css:1560,1561,1567,1578,1597,1601,
1651,1654,1656,1676,1679,1681,1712`. `--folio-focus` is only defined inside
`@media (forced-colors: active)` at `:1733`.
`tests/tokens.test.ts` pins defined tokens to a fixture but does not detect
undefined references.

## Root cause
Token rename/refactor left stale references in the command-palette and
skeleton CSS blocks; no lint rule or test checks reference resolution.

## Proposed minimal fix
Map each stale reference to the current canonical token (e.g.
`--folio-radius-card`/`--folio-radius-control`, `--folio-surface-elevated`,
`--folio-accent-container`) or add the intended definition to `tokens.css` and
`tests/fixtures/tokens.json` deliberately. Ensure `--folio-focus` is defined
for normal themes.

## Regression test
Add a test that parses all `src/styles/*.css`, collects `var(--folio-x)`
references (ignoring those with fallbacks), and asserts every name is defined
in `tokens.css`. This extends the existing tokens test without touching the
byte-pinned fixture unless a token is intentionally added.

## Status / residual risk
**Fixed & verified (automated).** Mappings were chosen by role, not blindly:
palette input/list use `--folio-radius-control`, skeleton cover uses
`--folio-radius-cover`, skeleton bar uses `--folio-radius-control`,
`--folio-bg-elevated` → `--folio-surface-raised`, and
`--folio-bg-active` → `--folio-accent-container`. `--folio-focus` now has a
literal definition in both `:root` and the dark theme (and in the byte-pinned
fixture), while the forced-colors override still wins. Reader-only tokens keep
their existing fallbacks, which a second test now guards. Residual risk: visual
comparison in a real window remains outstanding.
