# UI-012 — Edit-note textarea has no accessible name

- Classification: confirmed defect
- Severity: P2 Medium
- Confidence: confirmed
- Area: `src/screens/NotesScreen`
- Affected format/platform: all platforms
- First observed: 2026-11-28 baseline audit
- Commit/build: `ed7a3a1`

## User impact
In Notes, the edit-note dialog's textarea is announced as an unlabeled edit
field; users cannot confirm which field they are editing.

## Reproduction steps
1. Open Notes and choose Edit note on an annotation.
2. Inspect the focused textarea's accessible name with a screen reader or axe.

## Expected
Textbox named "Note" or similar.

## Actual
No `<label>` or `aria-label`; only a placeholder in some paths.

## Evidence
- `src/screens/NotesScreen.tsx:642-649` — `<textarea>` with value/onChange and
  no accessible name; dialog is named at `:630`.
- Compare `ReaderScreen.tsx:1485-1493` note editor, which also lacks a label —
  consider fixing both in one change.

## Root cause
Placeholder-only labeling pattern in note editors.

## Proposed minimal fix
Add `aria-label="Note"` to both the Notes edit textarea and the reader note
editor textarea.

## Regression test
Render both dialogs and assert `getByRole("textbox", { name: /note/i })`; add
an axe sweep with the dialog open.
