## Objective

Create a persistent, recoverable development knowledge system and a concise root
`AGENTS.md` so a future OpenCode session can resume without the original
conversation or VM state.

## Scope and constraints

- Inspect before writing; preserve existing docs and user changes.
- Do not modify application code.
- Do not commit, push, or change remotes without authorization.
- Use `docs/development/` as the knowledge base.
- Present the plan before implementation and wait for approval.

## What was inspected

- Root layout, `REMAINING.md`, `.github/workflows/desktop-ci.yml`, `.docs/01–09`.
- `desktop/package.json`, `pnpm-workspace.yaml`, `tsconfig.json`,
  `vite.config.ts`, `.env.example`, `.gitignore`.
- `desktop/README.md` and representative code: `FileStore`, `libraryPaths`,
  Rust guard/app-dir/lib command registration, `LibraryManager`, `model/types`,
  sync engine, token tests.
- Git status, branch tracking, remotes, recent commits, local config.
- Existing instruction files: none (`AGENTS.md`/`CLAUDE.md`/`.cursor*`/
  `opencode.json` absent).

## Findings that shaped the result

- All app commands must run from `desktop/`; the root has no manifest.
- Full Rust/Tauri verification is Windows-only in this environment.
- The main regression risks are schema-1 JSON compatibility, manifest write
  ordering, collection dual-writes, sync deletion semantics, and the
  TS-owned virtual path layout.
- `.docs/README.md` references absent `mobile/` and design-system files.
- `desktop/README.md` is a historical phase log; `REMAINING.md` is the current
  status source.
- `pnpm` is not installed in this VM, but `desktop/node_modules` is available.

- Do not introduce a backup automation that would run only inside the VM.
